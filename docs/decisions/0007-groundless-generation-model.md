# ADR-0007: Groundless generative-surface model controlled by Aios

**Status:** Accepted
**Date:** 2026-08-16

## Context

The generative surface has two candidate implementations:

1. **Surface IR** — the model emits a closed JSON vocabulary (`metricCard`,
   `sensorGauge`, `statusList`, `chart`, `notice`) that a deterministic
   renderer lays out. This is what `docs/ui.md` and
   `docs/m8-ui-repair-plan.md` describe.
2. **Unrestricted HTML** — the model emits a self-contained HTML/CSS panel.

The Surface IR path repeatedly failed to produce useful output. The closed
vocabulary and deterministic renderer constrain the model below its ability,
and the deterministic renderer flattens whatever it receives into generic
dashboard cards. The unrestricted HTML path produced genuinely good widgets
from the same evidence.

The existing "no raw HTML" rule (`m8-ui-repair-plan.md` §2.4) was written to
protect against two things: (a) model output executing code or reaching
privileged APIs, and (b) the model fabricating machine facts. Both concerns
are real, but forbidding HTML is not the only way to satisfy them.

## Decision

The surface is generated by a **groundless model** whose only connection to
the system is the relay from Aios:

```text
user request ──► Aios ──► planner ──► specialists ──► data
                                                     │
                          Aios verifies data answers ─┘
                          the request (coverage)
                                                     │
                          Aios relays (prompt + data)▼
                          ──► generation model ──► free HTML
                                                     │
                          Aios verifies values are ──┘
                          unchanged (fidelity)
                                                     ▼
                                               rendered widget
```

- The generation model receives only `(user prompt, specialist data)`
  relayed by Aios. It has no tools, no backend, no network, and no surface
  control.
- **Presentation is unconstrained.** The model may choose any HTML, CSS,
  layout, typography, density, or visualization.
- **Values are protected.** The model may not change a numeric value or invent
  one the specialists did not report. It may re-shape a value (formatting,
  unit rendering, gauge position) but not alter its magnitude.
- Aios owns the surface lifecycle: coverage verification, relay, value
  fidelity verification, display, sizing, docking, and iteration.

This supersedes `m8-ui-repair-plan.md` §2.4 ("a model must never stream raw
HTML") and the closed-vocabulary Surface IR as the shipped path. The prior
surface JSON schema is retained for its validator/evidence machinery only as
long as it is useful.

## Consequences

- The generation model output is treated as untrusted presentation. It is
  rendered in a surface window with no privileged IPC access and no backend
  reach.
- Coverage is checked before relaying: if specialist data does not answer the
  request, Aios does not call the generation model and fails visibly (ADR-0003).
- Value fidelity is checked after generation: displayed values marked with a
  `data-aios` contract must match the specialist data, or the surface is
  rejected.
- The two-agent design (Planner + Verification) is unchanged; the generation
  model is a separate groundless role, not a replacement for either.
